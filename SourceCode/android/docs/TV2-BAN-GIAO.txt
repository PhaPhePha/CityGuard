CITYGUARD — BÀN GIAO ANDROID TV2
Ngày: 27/11/2026

1. PHẠM VI VÀ LUỒNG ĐÃ TRIỂN KHAI
Chỉ sửa Android TV2. Backend TV5 và PostgreSQL không thay đổi.
Google Credential Manager / Facebook Login SDK → Firebase Auth → Firebase ID Token mới
→ POST /api/v1/auth/firebase → JWT CityGuard → SessionManager → màn hình chính.
Chỉ lưu accessToken, refreshToken CityGuard và users.id; không lưu social token vào SessionManager.
Phiên Firebase/Facebook được dọn sau khi xác thực. Hủy OAuth, lỗi 401/409, token rỗng,
callback trễ/trùng và endpoint chưa tồn tại không được tạo phiên đăng nhập thành công.
Giữ login username/password và flow report/map/profile hiện có.
Đã xóa nút/icon/dialog Instagram theo yêu cầu; chỉ giữ Google/Facebook.

3. HỢP ĐỒNG API BÀN GIAO TV5
POST /api/v1/auth/firebase
Content-Type: application/json
Android không gắn JWT cũ vào request auth.

Google:   {"idToken":"<Firebase ID Token>","provider":"GOOGLE"}
Facebook: {"idToken":"<Firebase ID Token>","provider":"FACEBOOK"}
Không gửi Google ID token/Facebook access token trực tiếp đến API này.

Response 200 giữ đúng envelope login hiện tại:
{
  "success": true,
  "message": "Đăng nhập thành công",
  "data": {
    "accessToken": "<CityGuard JWT>",
    "refreshToken": "<CityGuard refresh token>",
    "tokenType": "Bearer",
    "expiresIn": 1800000,
    "userInfo": {
      "id": 7,
      "username": "cityguard_user",
      "email": "user@example.com",
      "displayName": "Tên người dùng",
      "role": "USER"
    }
  }
}
expiresIn là MILLISECOND theo backend hiện tại. id là users.id PostgreSQL > 0.
Lỗi giữ cấu trúc message hiện tại để Android hiển thị; token sai/hết hạn → 401,
user khóa → 403, xung đột cần liên kết tài khoản → 409.

4. TV5 CẦN HOÀN THIỆN — CHƯA TRIỂN KHAI TRONG PHẦN TV2
- Firebase Admin SDK; credential qua biến môi trường/secrets, cùng Firebase project.
- Verify chữ ký/project/issuer/expiry theo Admin SDK và đối chiếu provider đã xác minh.
- Lấy UID/email/displayName/avatar từ danh tính đã xác minh, không tin Android tự khai.
- Tạo user lần đầu; đăng nhập sau dùng lại users.id, cập nhật profile theo chính sách.
- Email trùng local: yêu cầu xác thực tài khoản local để liên kết, giữ users.id cũ.
  Nếu chưa có luồng liên kết, trả 409 rõ ràng; không tự gộp chỉ theo chuỗi email.
- Migration auth_provider, provider_subject (Firebase UID), avatar_url nếu chưa có;
  UNIQUE(auth_provider, provider_subject). Liên kết nhiều provider phải giữ cùng users.id.
- Xử lý đăng nhập đồng thời bằng unique constraint/transaction phù hợp.
- Phát JWT CityGuard qua logic login hiện tại.
- Report/vote/comment tiếp tục tham chiếu users.id.
- Không lưu password Google/Facebook hoặc social access token vào PostgreSQL.

5. NGHIỆM THU THẬT CÙNG TV5 — CHƯA ĐƯỢC ĐÁNH DẤU PASS
1) Google lần đầu tạo đúng một user.
2) Google lần sau dùng lại users.id cũ.

6) Firebase ID token sai/hết hạn: backend trả 401, Android không vào main.
7) Profile/My Reports/report/vote/comment thuộc đúng người dùng.
8) Login/register username/password vẫn hoạt động.
Unit test và UI test dùng fake chỉ chứng minh hành vi Android, không chứng minh
đăng nhập thật trên Firebase/Meta/backend đã thành công.
