A. ĐỐI CHIẾU 6 VIỆC TV2

01. Login/Register khớp API, status 201/401/409 và validation
Trạng thái: ĐÃ CÓ CODE + ĐÃ TEST TỰ ĐỘNG; chờ kiểm thử API thật.
- Login gửi account/password; Register gửi username/email/password/displayName.
- Ràng buộc username, email và password đối chiếu được với DTO backend.
- requireApiData nhận 2xx, gồm 201; ưu tiên message lỗi của backend.
- Register thành công quay về Login, chỉ điền account, không tự lưu JWT/vào main.
- Không tự gửi lại auth POST khi lỗi kết nối; timeout đăng ký không khẳng định server chưa tạo user.
Bằng chứng: AuthApi.kt; ApiErrors.kt; AuthViewModel.kt; RegisterScreen.kt;
AuthViewModelTest, LoginNavigationTest.

02. Lưu token/user id, logout và hết hạn phiên
Trạng thái: ĐÃ CÓ CODE + ĐÃ TEST TỰ ĐỘNG; chưa nghiệm thu đóng/mở app trên máy thật.
- DataStore lưu accessToken + refreshToken JWT CityGuard, users.id và expiresAt.
- expiresIn là MILLISECOND, khớp buildAuthResponse của backend hiện tại.
- Thiết kế hiện tại: hết hạn/401 API bảo vệ thì xóa phiên và về Login; KHÔNG tự refresh.
  Đây là một trong hai phương án được nhiệm vụ cho phép. Có lưu refreshToken không có nghĩa đã tự refresh.
- Logout xóa phiên local trước; thu hồi refresh token phía server theo best effort,
  tối đa 3 giây. Offline vẫn logout trên máy, không bảo đảm server đã thu hồi token.
- Response 401 cũ không xóa phiên mới nhờ clearIfTokenMatches.
- SessionManagerTest kiểm tra tạo instance mới đọc lại DataStore; chưa tương đương
  force-stop/khởi động lại máy/đóng-mở app trên thiết bị thật.
Bằng chứng: SessionManager.kt; AuthViewModel.kt; ApiClient.kt; MainActivity.kt;
SessionManagerTest, AuthViewModelTest.

04. Đồng bộ username, email, displayName, role, summary
Trạng thái: DTO/contract ĐÃ KHỚP khi đối chiếu source hai phía; chờ API thật.
- Summary là object PHẲNG: id, username, email, displayName, avatarUrl, role,
  reportCount, confirmedReports. Không có field con tên summary trong JSON hiện tại.
- username/role có trong DTO; bố cục Profile hiện chỉ hiển thị displayName/email.
  Nếu nhóm muốn hiển thị thêm username/role, cần chốt thay đổi UI với prototype.
- avatarUrl đã được nhận và được render trên UI; thiếu/lỗi ảnh dùng icon mặc định.
- Ô "Bị phản hồi" hiện dấu —; contract chưa có chỉ số này. Không điền số giả.
- confirmedReports hiện được backend tính bằng số vote CONFIRMED do user gửi,
  không phải số report do user tạo đã được xác nhận. Giữ đúng ý nghĩa khi bàn giao.
Bằng chứng: ProfileSummaryDto; UserProfileSummaryResponse.java;
ProfileServiceImpl.getProfileSummary; ProfileScreen.kt.
